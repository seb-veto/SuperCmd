# Raycast in VV

Experimental Raycast replica inside VV, powered by BB server. Open **Raycast** from plugin navigation, or http://127.0.0.1:38986/plugins/vv-raycast/launcher. Full Raycast parity is unfinished.

The foundation is the MIT-licensed [SuperCmd fork](https://github.com/seb-veto/SuperCmd), upstream commit `2da7b9e5dec0199a972a59cece402c85f729d5d7`. The command-row, action-panel, calculator-card and Notes block-editor renderers plus fuzzy search matcher are reused under `vendor/`, and the donor’s local file index is reused directly, with bounded imports and accessibility adapted for VV. The standalone Electron process and its AI accounts are not started. The Raycast glyph in `assets/mark.svg` comes from [Simple Icons](https://github.com/simple-icons/simple-icons/blob/develop/icons/raycast.svg), CC0; its license is alongside it.

App search reads the enrolled local macOS host’s application folders, with real app icons. Open validates against a fresh catalog and launches only that selected application. Hidden app backups are excluded; no shell command is constructed. Search, arrows, Enter and Cmd-1…9 select/open items; Cmd-K opens searchable actions, Escape returns focus, Cmd-F favorites, and Cmd-E edits saved commands. Shortcuts are scoped to this plugin.

File Search appears inline in Root Search and in **Search Files**, with metadata details and Open, Show in Finder and Copy Path actions. Names come from the donor’s on-demand local index plus Spotlight; explicit home-folder paths resolve directly. Hidden paths, caches, Library and `.gitignore`, `.ignore`, `.rayignore` and repository exclude rules are checked before returning or opening a selection. The first scan streams partial matches. The donor’s1.2-million-entry cap is visible when reached; this Mac reached it, so complete name-search coverage is not qualified. A fresh native replay finds the known project folder by name after the initial query; an early empty snapshot was not evidence of a persistent miss. File identities and five-minute selection tokens are checked again before opening. This does not read file contents except ignore configuration. Native permissions still apply.

The calculator reuses the donor’s two-column card with Math.js for bounded arithmetic, percentages, scientific functions and units; Enter copies a result. Only numeric expressions and recognized units/functions pass validation; assignment, member access, arrays, arbitrary functions and non-finite/complex results are refused. Currency rates, natural-language dates/times, color conversion and paste-to-another-app remain unfinished. The donor’s closed-source SoulverCore binary requires a commercial license and is not bundled.

AI Chat uses BB’s native composer and ThreadChat for provider sessions, models, environments, streaming, stop, approvals and history. The Chat Settings sidebar controls the owned native composer’s model, reasoning and tier; existing chats keep their provider. It shows inherited permissions without changing them. Native picker Escape closes that picker first, then settings Escape restores the settings trigger. The chat sidebar groups native project chats, pins and local calendar dates, orders by native activity, supports title search and Command/Control1–0 switching, and pins, renames and archives the same native BB threads. It collapses on narrow screens. Quick AI has a separate compact surface; Tab opens it, and Cmd-J expands the same conversation/draft into AI Chat. With text in Root Search, Tab/Ask AI now creates a one-shot intent and submits through the native composer once its draft and selections are ready. Empty Tab opens a draft. Leaving before submission cancels the intent; reload and submission errors never replay it automatically. A React context around only this plugin’s embedded composer identifies the target, so unrelated composers receive no submission. This path has unit proof and empty-draft native navigation proof; nonempty live submission has not consumed another provider test. It does not paste into another app or collect screen/clipboard context.

**Create AI Command** saves a name and prompt. `{selection}` means text entered explicitly in the command input. Continue substitutes that input into a BB draft; Send starts execution. Input and native drafts survive reload. Cmd-Enter saves an edited command. Unconfirmed initial submissions are persisted and never automatically retried. Saved commands use revision checks to refuse stale overwrites. Commands live in this plugin’s SQLite; conversations, pinning, archive state and titles live in BB. Theme and favorites stay in the browser profile.

## Build and runtime

Use the intended VV cohort’s CLI, currently `/Users/seb/.bb-local/bin/bb`, with `BB_SERVER_URL=http://127.0.0.1:38986`. The qualified installed runtime/build is SDK0.6.56. Never launch an older VV variant against the shared data to build this plugin.

Quicklinks support Root Search and a tagged library, a Name/Icon/Link/Open With editor, explicit argument prompts with URL encoding, duplicate drafts, pin/hide/copy/edit actions and confirmed deletion. SQLite revisions reject stale edits, opens and deletions. Unsaved creation/edit drafts survive leaving the editor; stale drafts can explicitly reload the saved version. The argument parser and prompt layout adapt the donor’s implementation without importing its Electron or clipboard store. On macOS, OS open uses literal arguments and a freshly checked application catalog; file destinations are confined to Home. Native UI qualification covers the unsaved editor and empty library only. Persistence/CAS and OS dispatch use isolated tests with an injected runner; no live saved Quicklink or external destination was opened for QA. Favicons, imported/shared libraries, browser-tab reuse, non-Home files and implicit clipboard/selection/date/snippet placeholders remain incomplete.

Root Search uses the donor’s Unicode-aware fuzzy matcher: abbreviations such as `msg` and `slk`, word initials, accents and multiple terms work across titles and secondary fields. Local aliases use strict lowercase letter/number/space prefixes, with badges, collision checks and an editor in Actions. Exact aliases lead alias prefixes and title matches. Successful local navigation or acknowledged OS opens learn a bounded local frequency/query history; stale data decays without rewriting timestamps on render. Reset Ranking clears only that item’s history. Empty-search Favorites have a dedicated section and explicit Move Up/Down actions; typed queries keep relevance first. Selection follows the item identity through asynchronous result insertions, including renewed file selection tokens. Aliases, learning and Favorites are per VV browser profile, without global hotkeys or cross-device sync. Native checks cover fuzzy results and an unsaved alias dialog; saved personalization/learning has isolated-test proof only.

Root URL detection is a separate source draft on `vv/url-search`, outside the pending compact-mode activation. It reuses the donor URL parser for domains, HTTP/HTTPS, localhost, ports and IPv4/IPv6, inferring HTTPS for a bare address. It rejects credentials, whitespace, file paths, unrelated schemes and version-like numbers. A transient normalized URL row has Open, Copy and Create Quicklink actions; typing alone does not fetch a page, open a browser, save history or create a Quicklink. Server and host independently validate the destination, then reuse the literal OS opener for the default browser. No extra agent execution tool is registered. Isolated tests exercise normalization/rejection, server/host boundaries and ranking; no native URL activation or actual OS open has been tested.

General → Appearance now includes Standard/Compact Window Mode, with a Root command, Actions entry and Command/Control comma shortcut. Compact collapses an empty Root Search to a 64px search bar; typing and Actions expand it, and empty suggestions collapse on Escape or loss of focus. Arrow/Enter and numbered shortcuts first reveal hidden suggestions instead of running an invisible item. Typed text and other editors retain their normal layout and state. The mode is stored in this VV browser profile, with storage errors surfaced. The source build and isolated behavior tests pass; this increment awaits approval to reload the live plugin and run native acceptance.

Chat Settings docks beside the conversation at wide widths, preserving the shared header/composer column; narrow windows use an overlay that stays inside the plugin. Existing chat titles are editable through BB’s rename action. Unsaved title edits survive closing/reopening settings while the same chat remains mounted; Reload Title discards the edit explicitly. A native-title read check rejects a known stale edit, and an already-matching title reconciles a lost response without repeating the update. This is a read-before-write guard, not an atomic BB compare-and-swap. No title is saved or message sent merely by typing or closing the panel. Model/reasoning/tier and execution permissions continue through the native BB composer.

The separate `vv/notes-history` draft fixes first-edit Undo before the typing checkpoint, deduplicates history frames, preserves full block metadata and invalidates Redo after new typing. Structural actions checkpoint before mutation; Undo/Redo restore existing DOM synchronously and complete new blocks during layout, without a later animation-frame text write. The actual previous callback was exercised with injected DOM/frame refs to demonstrate the missed first edit and a delayed restore overwriting a newer edit. History fixtures pass; this is source/isolated proof, not native Notes editing acceptance, and it is outside the pending compact-mode activation.

Notes reuse the donor’s real block editor, with Markdown shortcuts, a slash menu, formatting controls, tasks, code blocks and block reordering. They live in an embedded VV workspace with a stack browser, title/body search, pin/color controls and Recently Deleted restoration. BB plugin SQLite owns saved notes; a serial autosave coordinator keeps recovery drafts, handles edits during a save, preserves clearing a note, and rejects stale overwrites. Identical retries reconcile lost save responses under the same note identity/revision. Rendering uses BB Markdown plus safe React underline markup, without the donor’s raw HTML injection or Electron link bridge. Native checks cover empty-note controls, search/browse, focus, toolbar/slash menus and narrow layout; saved editing/recovery/formatting still needs native acceptance. Multi-block inline selections are refused to preserve note content. Images, nested-list structure, document find, export/import, Send to AI Chat, floating OS windows and automatic deleted-note expiry are incomplete.

The public npm declaration package remains pinned to0.6.49 because0.6.56 is not published. This increment typechecks and tests against that public0.6.49 package and is built/served by the canonical0.6.56 CLI/runtime. No private SDK or absolute local dependency is published. `bb plugin types` requests0.6.56 but cannot install it from npm yet; its pin warning is an acknowledged tooling mismatch, not authority to downgrade the shared runtime. Tests importing the donor TypeScript source require Node22.18 or newer.

Run `npm ci`, `bb plugin build`, `npx tsc --noEmit`, and `npm test`. With a complete matching SDK supplied locally, install it using `npm install --no-save --package-lock=false <sdk-directory>` before those checks. Install into the intended server with `bb plugin install . --yes`; later changes use `bb plugin build` and `bb plugin reload vv-raycast`.

`bb vv-raycast commands|chats|quicklinks --json`, `bb vv-raycast notes "query" --json`, `bb vv-raycast calculate "10ft in m" --json`, and `bb vv-raycast files "query" --json` expose read-only capabilities. The `vv_raycast_commands`, `vv_raycast_calculate`, `vv_raycast_files`, `vv_raycast_quicklinks` and `vv_raycast_notes` tools expose those read-only capabilities. `vv_raycast_note` reads one exact saved note ID. Search builds local metadata when needed; none of these execute AI commands or open files. General agent execution parity remains open.
