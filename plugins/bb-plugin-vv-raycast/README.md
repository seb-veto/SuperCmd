# Raycast in VV

Experimental Raycast replica inside VV, powered by BB server. Open **Raycast** from plugin navigation, or http://127.0.0.1:38986/plugins/vv-raycast/launcher. Full Raycast parity is unfinished.

The foundation is the MIT-licensed [SuperCmd fork](https://github.com/seb-veto/SuperCmd), upstream commit `2da7b9e5dec0199a972a59cece402c85f729d5d7`. The command-row, action-panel and calculator-card renderers are reused under `vendor/`, and the donor’s local file index is reused directly, with bounded imports and accessibility adapted for VV. The standalone Electron process and its AI accounts are not started. The Raycast glyph in `assets/mark.svg` comes from [Simple Icons](https://github.com/simple-icons/simple-icons/blob/develop/icons/raycast.svg), CC0; its license is alongside it.

App search reads the enrolled local macOS host’s application folders, with real app icons. Open validates against a fresh catalog and launches only that selected application. Hidden app backups are excluded; no shell command is constructed. Search, arrows, Enter and Cmd-1…9 select/open items; Cmd-K opens searchable actions, Escape returns focus, Cmd-F favorites, and Cmd-E edits saved commands. Shortcuts are scoped to this plugin.

File Search appears inline in Root Search and in **Search Files**, with metadata details and Open, Show in Finder and Copy Path actions. Names come from the donor’s on-demand local index plus Spotlight; explicit home-folder paths resolve directly. Hidden paths, caches, Library and `.gitignore`, `.ignore`, `.rayignore` and repository exclude rules are checked before returning or opening a selection. The first scan streams partial matches. The donor’s1.2-million-entry cap is visible when reached; this Mac reached it, so complete name-search coverage is not qualified. A fresh native replay finds the known project folder by name after the initial query; an early empty snapshot was not evidence of a persistent miss. File identities and five-minute selection tokens are checked again before opening. This does not read file contents except ignore configuration. Native permissions still apply.

The calculator reuses the donor’s two-column card with Math.js for bounded arithmetic, percentages, scientific functions and units; Enter copies a result. Only numeric expressions and recognized units/functions pass validation; assignment, member access, arrays, arbitrary functions and non-finite/complex results are refused. Currency rates, natural-language dates/times, color conversion and paste-to-another-app remain unfinished. The donor’s closed-source SoulverCore binary requires a commercial license and is not bundled.

AI Chat uses BB’s native composer and ThreadChat for provider sessions, models, environments, streaming, stop, approvals and history. The Chat Settings sidebar controls the owned native composer’s model, reasoning and tier; existing chats keep their provider. It shows inherited permissions without changing them. Native picker Escape closes that picker first, then settings Escape restores the settings trigger. The chat sidebar searches titles, and pins, renames and archives the same native BB threads. It collapses on narrow screens. Quick AI has a separate compact surface; Tab opens it, and Cmd-J expands the same conversation/draft into AI Chat. With text in Root Search, Tab/Ask AI now creates a one-shot intent and submits through the native composer once its draft and selections are ready. Empty Tab opens a draft. Leaving before submission cancels the intent; reload and submission errors never replay it automatically. A React context around only this plugin’s embedded composer identifies the target, so unrelated composers receive no submission. This path has unit proof and empty-draft native navigation proof; nonempty live submission has not consumed another provider test. It does not paste into another app or collect screen/clipboard context.

**Create AI Command** saves a name and prompt. `{selection}` means text entered explicitly in the command input. Continue substitutes that input into a BB draft; Send starts execution. Input and native drafts survive reload. Cmd-Enter saves an edited command. Unconfirmed initial submissions are persisted and never automatically retried. Saved commands use revision checks to refuse stale overwrites. Commands live in this plugin’s SQLite; conversations, pinning, archive state and titles live in BB. Theme and favorites stay in the browser profile.

## Build and runtime

Use the intended VV cohort’s CLI, currently `/Users/seb/.bb-local/bin/bb`, with `BB_SERVER_URL=http://127.0.0.1:38986`. The qualified installed runtime/build is SDK0.6.56. Never launch an older VV variant against the shared data to build this plugin.

The public npm declaration package remains pinned to0.6.49 because0.6.56 is not published. This increment typechecks and tests against that public0.6.49 package and is built/served by the canonical0.6.56 CLI/runtime. No private SDK or absolute local dependency is published. `bb plugin types` requests0.6.56 but cannot install it from npm yet; its pin warning is an acknowledged tooling mismatch, not authority to downgrade the shared runtime. Tests importing the donor TypeScript source require Node22.18 or newer.

Run `npm ci`, `bb plugin build`, `npx tsc --noEmit`, and `npm test`. With a complete matching SDK supplied locally, install it using `npm install --no-save --package-lock=false <sdk-directory>` before those checks. Install into the intended server with `bb plugin install . --yes`; later changes use `bb plugin build` and `bb plugin reload vv-raycast`.

`bb vv-raycast commands|chats --json`, `bb vv-raycast calculate "10ft in m" --json`, and `bb vv-raycast files "query" --json` expose read-only capabilities. The `vv_raycast_commands`, `vv_raycast_calculate` and `vv_raycast_files` tools do the same. Search builds local metadata when needed; none of these execute AI commands or open files. General agent execution parity remains open.
